# Panduan Revisi Laporan (Modul Lama)

Skill ini digunakan saat diminta untuk mengaudit, mengoreksi, atau memperbarui Laporan Modul 1 sampai Modul sebelumnya berdasarkan data lapangan yang baru masuk.

## 🔄 PROTOKOL REVISI
1. **Jangan Membabat Habis Paragraf Lama:** Jika user berkata "jangan mempersingkat", artinya Anda hanya perlu mengganti substansi kalimat yang salah/ketinggalan zaman, dan *append* (menambahkan) temuan baru di akhir paragraf atau list. Pertahankan narasi yang sudah disetujui sebelumnya!
2. **Harmonisasi Silang:** Jika Modul 3 direvisi, cek apakah itu berdampak pada Modul 4 (Scope) atau Modul 2 (Stakeholder).
3. **Ceklis Mermaid Usang:** 
   - *Matriks Prioritas* (M3): Pastikan tidak ada "karena belum ada aplikasi web" di dalamnya (solusi kita adalah Tata Kelola/Governance).
   - *Power-Interest Grid* (M2): Pastikan posisinya tepat (Q1, Q2, Q3, Q4).
   - *Interkoneksi Sistem* (M4/M5): Pastikan sinkronisasi pelaporan (Dekanat, LAM-INFOKOM) terdeskripsi dengan benar sebagai proses operasional/manual-ekstraksi, bukan integrasi API database otomatis dari SLiMS.

## ✍️ STANDAR ANTI-AI TETAP BERLAKU
- Saat menambah kalimat revisi, pastikan bebas dari EM-DASH (`-`).
- Gunakan bahasa konkret: sebut nama narasumber, peran jabatannya, dan nama file sumber jika perlu (misal: "Berdasarkan wawancara `[WAW-001]` dengan Pustakawan...").
